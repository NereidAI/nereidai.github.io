# NereidFleet 入门

!!! warning "技术预览（Tech Preview）——设计阶段"
    Fleet 处于早期设计阶段（v0.1 草案）。当前仓库以设计文档、调研与拟议的
    架构决策为主，尚非可运行产品；目前还没有可供安装的运维控制台。本篇描述
    的是预期的首次使用路径与当前的仿真验证，而非已完成的工作流。

NereidFleet 是规划中的具身智能机器人车队管理、操控与协同平台，覆盖轮式
AMR、四足、人形与平衡机器人。它将提供带实时状态的机器人台账、多机器人任务
派发与交通协调、远程操作与急停，构建在 ROS 2、Eclipse Zenoh、Open-RMF 与
EdgeX Foundry 的开放技术栈之上。

## 它将做什么

- **管理**——资产台账、车队分组、边缘节点管理、地图、权限与审计。
- **操控**——单机远程操作、急停、安全模式切换，以及实时状态与遥测。
- **协同**——多机任务编排、交通管制、冲突消解与跨车协作。

## 当前状态

技术预览阶段没有可供运维人员部署的内容。项目采用“先仿真、后实物”的路线，
工程里程碑为：

1. **阶段 0——纯仿真（零硬件）**：用经过验证的 Free Fleet 多车示例，配合
   Open-RMF 与 Zenoh ROS 2 DDS 桥接，端到端验证任务派发与交通协商。
2. **阶段 1——轮式机器人 PoC**：适配第一台轮式 AMR（首个目标平台），把
   至少两台机器人接入同一 Zenoh 总线，并搭出最小化的台账/任务/遥测 API 与
   Web 界面。
3. **阶段 2——边缘与北向**：接入 EdgeX，预研云端主控场景下的
   VDA5050 over MQTT，并扩展到四足与人形机器人。

仿真阶段建议的环境为 Ubuntu 24.04、ROS 2 Jazzy、Cyclone DDS RMW、
Zenoh 1.5 及以上版本，以及 Open-RMF。与 Edge → Forge → Horizon → Link
闭环的集成属于后续工作。

!!! danger "安全责任在车端"
    平台急停绝不是唯一的停机手段。每台机器人都必须保留车端硬件急停或独立
    安全回路，确保网络或总线故障时仍能安全停机。
