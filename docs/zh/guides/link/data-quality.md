# 数据质量

每条[遥测](glossary/telemetry.md)数据都带有一个**质量（quality）**标记。它回答的问题与设备[连接状态](glossary/presence.md)不同：连接状态说明设备是否在线，而质量说明这条已收到的数值本身是否可信。

## 三个标记

| 标记 | 含义 | 何时产生 |
| --- | --- | --- |
| `GOOD` | 有效、在量程内、转换成功。 | 所有被接受数据的默认值。 |
| `UNCERTAIN` | 可疑但仍可使用。 | 平台从不自动标记 —— 仅租户的存储钩子（storage hook）脚本可设置。 |
| `BAD` | 无效或不可用。 | 描述符转换失败，或转换后的值超出描述符的有效量程。 |

## 质量如何判定

- 格式正确的布尔、字符串或数值默认为 `GOOD`。
- 没有匹配到配置描述符的数值按未转换形式存储，并保持 `GOOD` —— 平台不会自行猜测。
- 当配置描述符应用了转换（线性、查表、表达式、枚举、恒等）时：
  - 转换脚本报错 → `BAD`；
  - 转换后的工程值超出描述符的 `valid_min`/`valid_max`（若已设置）→ `BAD`；
  - 其余情况 → `GOOD`。
- 文本结果（例如枚举标签）始终视为在量程内；仅数值结果参与量程校验。
- 租户可在**存储钩子**脚本中返回 `quality` 字段来改写该标记。

该标记随数据一同存储，由遥测查询返回，作为 `metadata.quality` 暴露给[规则链](glossary/rule-chain.md)，并在设备的**全部测点**表格中显示为彩色标签（`GOOD` 为绿色，其余为红色）。

## 有什么用

设备可能完全在线，却报出一个不应据以行动的值 —— 传感器故障、超出物理量程，或标定表达式损坏。质量让仪表盘、告警和规则链能区分"收到了一个数"与"这个数是可靠的"，因此异常读数仍可被留存以供排查，而不会触发告警。
