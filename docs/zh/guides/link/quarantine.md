# 隔离

隔离是对**单台设备**施加的可逆事件响应锁。当设备疑似凭据泄露、被盗、洪泛或行为异常，你需要立刻让它停下、但又不想销毁其历史时，使用该功能。

## 隔离做了什么

- 将设备置为 `QUARANTINED` [生命周期状态](glossary/lifecycle.md)。
- 驱逐 [presence](glossary/presence.md) 并立即断开在线会话。
- 使后续认证失败：设备无法重连、无法上报[遥测](glossary/telemetry.md)、无法接收命令 —— 尽管其凭据仍保留在册。
- 触发一条 CRITICAL 级别告警。
- 记录执行人、时间以及原因。

隔离**不是**停用。身份、归属、遥测和历史全部保留，设备可以恢复到服务状态，无需重新开通。

## 原因码

隔离必须选择一个结构化原因码，并附自由文本说明：

| 原因码 | 适用场景 |
| --- | --- |
| `credential-compromise` | 疑似凭据泄露或被滥用。 |
| `device-stolen` | 设备疑似落入敌对者手中。 |
| `burst-flood` | 设备超出其声明的速率或突发预算。 |
| `firmware-anomaly` | 可疑的设备行为。 |
| `other` | 兜底选项。**此处必须填写说明**，以免原因码本身无法承载全部信息。 |

## 解除隔离

有两种路径，都会清除 CRITICAL 告警并记录审计事件：

- **直接解除** —— 由平台管理员在设备页面解除，并填写说明为何可以安全恢复。适用于事故原因已查明并已闭环的场景。
- **双人复核解除** —— 由平台运维人员从命令行开单，由超级管理员在 Web 控制台确认。适用于需要职责分离的决策。详见"系统管理"分组下的**运维工单**。

无论走哪条路径，设备都会回到此前的工作状态，且**原有凭据立即恢复可用** —— 无需重新签发。

## 查看被隔离的设备

被隔离的设备会出现在设备列表默认视图中，带有 `QUARANTINED` 徽标、隔离时间和原因。它们刻意不做隐藏：看不见的事故等于没有被处置。

## 注意事项

- 被隔离的设备是从**遥测写入和命令下发**层面被排除，而不仅仅是被断开连接。
- 解除隔离不会恢复任何已被删除的内容 —— 隔离本身不删除任何数据。
