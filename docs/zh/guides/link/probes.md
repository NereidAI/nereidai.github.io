# 网关探测

[**探测（Probe）**](glossary/probe.md)是按需的可达性检查：你让网关立刻确认它所管理的一组子设备在现场总线上是否应答。平台本身看不到现场总线，因此把所选设备按网关分组，向每个在线网关转发一帧聚合请求，再展示网关逐设备回报的结果。

## Probe 与命令、存活探测的区别

三者相关但不可互换：

- **Probe（按需探测）**——只回答“设备是否可达、往返时延多少”。不需要命令名，也不依赖命令目录；平台不解释结果内容，探测失败不会改变任何设备状态。
- **命令（Command）**——对设备执行真正的读或写（设点、触发动作）。命令必须先在命令目录声明，返回的是业务数据；persistent 命令在设备离线时会排队。
- **存活探测（`health_check`）**——配置在连接器实例上的常驻周期探测，自动驱动绑定设备的在线/离线状态。按需探测是一次性、手动的批量检查，不产生自动状态影响。

网关离线时其探测**不排队**：这些设备立即以“未连接”失败。

## 创建探测

1. 打开 **网关探测**，点击 **发起探测**。
2. 选择管理这些设备的 **网关**，列表会显示网关的实时在线状态。
3. 选择一个或多个 **子设备**（单任务最多 100 个），仅显示所选网关管理的 ACTIVE 子设备。
4. 选择 **模式**。平台只透传该值，具体语义由网关实现定义：
   - **缓存（cached）**——网关可使用最近一次检查结果回答。
   - **实时（fresh，默认）**——网关执行一次新的检查。
   - **严格（strict）**——网关按最严格的检查规则执行。
5. 设置 **单设备超时**（毫秒，默认 10000），然后发送。

## 筛选与查询

表格上方的工具栏在服务端过滤：

- **状态**——按聚合状态（待处理、进行中、全部成功、部分成功、失败）。
- **模式**——cached / fresh / strict。
- 搜索框按网关或被探测设备的名称/别名匹配（不区分大小写、支持部分匹配）。

## 查看结果

任务表显示每个探测的创建时间（按当前控制台语言格式化）、探测所针对的**网关**（Canonical name，下方显示别名，链接到网关详情页）、模式、**单设备超时**、实时进度条、成功/总数计数和聚合状态：

- `进行中`——仍在等待网关回报。
- `全部成功`——每台设备都成功回报。
- `部分成功`——部分设备失败或超时。
- `失败`——任务未取得成功即结束（例如涉及的网关全部离线）。

点击任务行（或 **查看**）打开结果抽屉：每行显示设备名称与别名并链接到设备详情页、逐设备状态，网关回报可达时显示 **可达** 及往返时延，否则显示失败错误（超时、无响应、网关未连接）。任务进行期间结果通过 WebSocket 实时更新；任务结果保留 24 小时。
