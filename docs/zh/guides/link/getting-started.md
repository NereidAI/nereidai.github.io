# NereidLink 入门

NereidLink 是套件中的私有化 IoT 数据管道：多协议设备接入、统一消息骨干、
规则引擎、告警与实时看板。一套代码以两种形态交付——all-in-one 单二进制或
Kubernetes 微服务。本篇是运维人员的首次上手路径：从一个空租户走到在总览页
看到实时遥测。

!!! tip "可独立运行"
    Link 本身就是一个完整产品。连接设备、查看数据不需要 Sphere、Identity 或
    任何其他产品。套件单点登录与门户只在把 Sphere 部署为入口时才生效——参见
    [默认可独立](../../products/index.md#standalone-by-default)。

## 前提条件

- 一个正在运行的 Link 实例（all-in-one 二进制或 Kubernetes 部署），以及其
  控制台地址。
- 一个具备配置、设备与凭据管理权限的控制台账号——独立部署时为 Link 本地
  账号；接入套件时为带 Link 角色的套件账号。
- 至少一个可接入对象：一台直接使用 MQTT/HTTP 的设备，或一个在现场汇聚
  子设备的[网关](glossary/gateway.md)（例如 Edge）。

## 1. 登录

打开 Link 控制台。独立部署时使用 Link 自己的账号登录；使用套件时，通常从
Sphere 门户免二次登录进入 Link。两种方式下控制台界面完全一致。

## 2. 创建设备配置

[设备配置](glossary/profile.md)把测点描述符分组——测点名称、值类型、单位以及
可选的转换。配置是可选的（没有配置也会照常存储数值），但先建好配置可以让
单位与工程值从第一帧数据起就是正确的。

1. 打开**配置**页面，点击**创建配置**。
2. 填写名称，必要时选择协议族（例如 `modbus`）。
3. 为设备上报的每个测点键添加一个描述符。

完整的描述符与转换选项见[设备配置](profiles.md)。

## 3. 注册设备

1. 打开**设备**页面，点击**创建设备**。
2. **规范名称**（`dev-xxxx`，网关为 `gw-xxxx`）由系统自动生成，是设备的
   稳定身份。
3. 选择上一步创建的配置（可选），并按需填写便于识别的别名。
4. 网关场景下，先创建一个**网关**类型的父设备，再为每台现场设备创建绑定到
   该网关的子设备。详见[设备](devices.md)。

## 4. 添加凭据

设备至少持有一个有效凭据才能连接。打开设备详情的**凭据**标签页并添加一条：
简单共享密钥用 `TOKEN`，此外还有 `PASSWORD`、`JWT`，mTLS 客户端证书用
`X509`。

!!! note "请立即复制密钥"
    新建密钥只明文展示一次，之后无法找回。离开页面前请把它保存到安全的
    地方。详见[设备凭据](credentials.md)。

## 5. 接入设备

按设备形态选择对应路径：

- **直连设备**——固件自身使用 MQTT（首选）或 HTTPS 长轮询，携带凭据连接
  Link 消息中间件并上报扁平遥测帧。参见[直连设备接入](integrate-direct-device.md)。
- **网关汇聚子设备**——一个进程持有单条 MQTT 连接，在其后汇聚大量现场
  设备。先注册并绑定子设备，再运行网关。参见[网关设备接入](integrate-gateway.md)；
  Edge 就是这条路径上现成的、基于 EdgeX 的网关。

## 6. 查看实时遥测

回到**总览**页。设备在首次 presence/遥测时变为**在线**，**遥测（1 小时）**
卡片开始计数，吞吐面板通过 WebSocket 实时更新——没有轮询。打开设备详情可
查看最新读数与图表。
