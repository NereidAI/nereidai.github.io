# 关于 NereidAI

<img class="nr-about-logo" src="/assets/logo.png" alt="NereidAI logo" width="120" />

## 名字的由来

**“Nereid”只是我们为项目选的吉祥物名字而已，并没有什么特别深奥的含义。**
在希腊神话里，Nereid（涅瑞伊得斯）是“海之精灵”，海神 Nereus 的女儿们。我们喜欢
这个意象，于是把它作为项目吉祥物，也作为每个产品共同的前缀。

## 吉祥物的寓意

把它想象成一位在数据海洋中游弋的精灵：

- **在数据的海洋中导航**——在 AIoT 系统的设备、模型与流水线之间找到路径；
- **帮助用户辨明方向**——把零散的边缘到云端技术栈，变成一条清晰的闭环；
- **提前发现水下暗礁**——厂商锁定、强制依赖云端、数据流出客户边界，以及模型始终
  无法抵达现场等隐患。

这些“暗礁”正是平台要帮助用户绕开的东西。

## 我们的使命

> **让 AIoT 民主化**：把边缘与云端工作流整合为一个无缝闭环——低延迟的边缘推理、
> 隐私保护的运营方式、自动化的模型监控，全部汇聚于同一个平台。

落到实处，就是让一支精干的小团队，也能持续把自己的业务数据变成在自家现场设备上
运行的模型：数据无需离开客户边界、不强制上云、平台也不绑定任何单一芯片或边缘
厂商。

## 家族如何命名

每个产品都以 **Nereid** 为前缀，后缀说明它的职责：

| 名称 | 后缀的含义 |
|---|---|
| NereidSphere | 把套件维系在一起的“球体（sphere）”——门户、网关、粘合 |
| NereidIdentity | 身份与访问 |
| NereidLink | 把设备“连接（link）”进平台 |
| NereidForge | “锻造（forge）”模型的工厂 |
| NereidHorizon | 抵达远方“地平线（horizon）”上的远程边缘节点 |
| NereidEdge | “边缘（edge）”，运行在现场网关 |
| NereidFleet | 机器人“机队（fleet）” |
| NereidMobile | “移动（mobile）”窗口 |

商业行业解决方案也沿用同样的意趣——NereidFactory、NereidSentinel、NereidMedical。
见 [命名与简写](../reference/naming.md)。

## 我们的信念

- **私有化设计**——完全气隙运行，无强制回连。
- **开源 + 商业支持**——Apache-2.0 社区版；企业 LTS 与交钥匙交付按商业条款提供。
- **产品松耦合**——每个产品都能独立存在，套件层只做联邦。见 [默认可独立](../products/index.md#standalone-by-default)。
- **厂商中立契约**——不硬依赖任何单一边缘技术栈或芯片厂商。
