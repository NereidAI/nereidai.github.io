# NereidEdge

Edge 是把现场设备接入 Link 的边缘代理；它运行在现场网关上，由
Horizon 交付并持续更新。

## 它解决什么问题

- 现场设备与传感器使用众多南向协议；Edge 把它们接入 Link，无需逐设备做
  云端集成。
- 边缘站点常处在不稳定甚至中断的广域网链路之后；本地缓冲与自治能力让平台不可达时
  数据与控制仍能工作。
- 大规模网关上线需要可重复且安全；网关通过安全连接接入 Link，并由平台下发的
  声明式配置驱动。
- 让边缘运行时及其配置在整群网关上保持一致是运维难题；Horizon 负责分发与
  更新，Edge 负责对账其声明状态。
- 运维人员需要看到网关及其挂接设备；Edge 上报在线状态、设备状态与周期性清单。

## 核心能力

**设备接入**

- 遥测桥接：把现场事件与读数转换为 Link 的网关遥测。
- 设备映射：将现场设备名与 Link 子设备建立关联。
- 生命周期管理：首次遥测时挂接设备，关停时断开，并按固定周期发送全量设备清单。
- 与网关上的 EdgeX Foundry 边缘栈协同运行。

**网关行为**

- 连接时进行强制握手与能力协商。
- 周期性心跳，与协商中约定的上限对齐。
- 平台托管设备属性在本地缓存，每次重连后刷新，并遵守删除语义。
- 设备影子：在连接时及变化时上报网关真实运行态。
- 网关级设置由平台下发并即时生效。

**声明式连接器**

- 连接器定义由平台下发；Edge 负责应用、更新与删除，回报状态，并自愈被移除的
  设备。
- 新增连接器类型无需改动平台或线协议；节点级导出连接器在路线图上。

**韧性**

- 经明文或 TLS 连接、以安全方式把 MQTT 传输到 Link。
- 面向断网运行设计：断点续传缓冲与基于游标的续传，让不稳定的广域网不丢数据。
- 内置健康检查与可观测性。

## 在套件中的位置

Edge 是闭环中的南向边缘一环，位于现场设备与 Link 之间，并由 Horizon
部署。

- **设备 → Edge**：边缘网关从南向 device service 采集事件与读数流。
- **Edge → Link**：遥测、在线状态、属性与影子上行；命令与连接器定义下行。
- **Horizon → Edge**：分发一环。Horizon 发布让 Edge 运行在
  网关上的服务定义与策略；Edge 自身不承载固件升级机制。
- **Forge**：Edge 在现场运行的模型与应用由模型工厂产出，并经 Horizon
  分发。
