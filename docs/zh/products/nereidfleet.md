# NereidFleet

Fleet 是面向具身智能机器人车队（轮式、四足、人形、平衡车）的管理、操控与协同
平台，构建在 ROS 2、Eclipse Zenoh、Open-RMF 与 EdgeX Foundry 的开放技术栈之上。

!!! warning "技术预览（Tech Preview）"
    Fleet 处于早期设计阶段（v0.1 草案）。当前仓库以设计文档与调研为主，实现将
    按下文的分期 PoC 路线展开。此处描述的是目标设计，而非已交付功能。

## 它解决什么问题

- 封闭的车队平台会把用户锁定在单一厂商与单一机型上；Fleet 旨在以开放技术栈
  统一管理、操控与协同。
- 异构机器人（轮式 AMR、四足、人形、平衡车）控制接口各不相同；Fleet 用统一的
  车队 / 机器人 / 任务 / 能力模型对其抽象。
- 把实时控制与平台流量混在一起会带来抖动与脆弱性；Fleet 将实时控制域与
  管理、遥测域分离。
- 现场会断网；边缘自治必须让机器人与边缘层在平台不可达时仍能安全运行。
- 引入平台不应强制替换车端中间件；Fleet 桥接现有 ROS 2 机器人，而非侵入改造。

## 核心能力

**管理**

- 资产台账、车队分组与边缘节点管理。
- 地图、权限与审计。

**操控**

- 单机远程操作与急停。
- 安全模式切换。
- 实时状态与遥测。

**协同**

- 多机任务编排。
- 交通管制与冲突消解。
- 跨车协作。

**架构思路**

- 数据与控制分离：车端本地控制闭环留在实时域以保证低延时与安全；平台观测、管理与
  任务走独立的数据总线，跨网段汇聚。
- 异构抽象：通过车队适配层把运动形态差异隐藏在统一模型之后。
- 桥接而非侵入：现有 ROS 2 机器人直接接入平台，无需替换其车端中间件。
- 经 EdgeX Foundry 提供边缘自治与异构传感器接入。
- 面向云端主控场景的行业北向协议（VDA5050 over MQTT）处于预研阶段。

## 在套件中的位置

Fleet 位于套件的现场 / 站点平面，与 Edge 及机器人本体一起运行在本地
局域网，而不在中心平台内。

- **Fleet → 机器人**：平台负责任务调度与遥控下发；机器人把状态与遥测回报平台。
- **Open-RMF**：负责全局任务分配、交通协商与资源冲突消解。
- **EdgeX Foundry**：负责异构传感器接入与边缘自治，与 Edge 使用同一套边缘框架。
- **闭环集成尚在未来**：Fleet 尚未接入
  Edge → Forge → Horizon → Link 闭环，是套件中处于早期阶段的
  新成员。参见 [套件总览](index.md)。
