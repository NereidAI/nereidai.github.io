# 安全

安全与可运维性是 NereidAI 的一等关切，而非事后补丁。平台被设计为在无互联网访问的
情况下运行，并把每一个字节都留在客户边界之内。

## 安全基线

| 能力 | 状态 |
|---|---|
| 气隙 / 离线安装（完整镜像包，无需互联网） | 已具备 |
| 无强制回连；数据留在客户边界内 | 已具备 |
| 服务间与服务到设备链路的 mTLS | 已具备 |

| 合规基线（如 等保 2.0）与本地 OS / 加速卡认证 | 逐项目路线图 |

## 纵深防御

整套件叠加了多层彼此独立的控制，而不依赖单一门槛：

- **网络隔离。** 产品运行期不依赖互联网、无强制回连；私有化构建只从内部镜像源与
  私有仓库拉取。见 [气隙安装](../deployment/air-gapped.md)。
- **传输完整性。** 服务间与服务到设备的流量以 mTLS 保护。边缘网关与平台之间的
  现场链路采用仅出站的 mTLS，并配合断点续传缓冲。
- **身份。** 套件唯一的一套身份平面是事实来源；门户从不存储用户。
  见 [SSO 与 OIDC](sso-oidc.md)。
- **授权。** 访问默认拒绝：身份证明你*是谁*，产品本地的 RBAC 决定你*能做什么*、
  *能触达哪些数据行*。见 [RBAC](rbac.md)。
- **密钥与静态数据。** 租户密钥与存储的凭据在静态时以库外保存的主密钥加密；明文
  只在真正需要处还原。
- **完整性与溯源。** 审计记录构成追加式、可防篡改的哈希链；投递到现场的服务部署
  经过签名。签名发布产物与逐版本 SBOM 已在路线图上。

!!! note "服务间零信任"
    产品之间从不直接访问对方的数据存储。产品通过各自文档化的 API 与消息骨干通信，
    套件层不携带业务逻辑——因此不存在一个会放大故障半径的共享数据库。

## 身份与访问

两个套件服务构成安全平面，且对单产品部署都是可选的：

- **Identity** —— 套件认证与身份中心：覆盖所有产品的单点登录、
  OIDC / LDAP / SAML 联邦、粗粒度套件角色、令牌签发，以及租户级访问治理。身份引擎
  可替换：任何满足已发布契约的 OIDC/OAuth2 引擎都可以顶上。
- **Sphere** —— 套件门户，也是**唯一**与身份平面对接 OIDC 的组件。它把经过
  验证的身份交给产品，且从不看到或存储产品密码。

两种产品集成模式的详细走查见 [SSO 与 OIDC](sso-oidc.md)；角色与租户模型见
[RBAC](rbac.md)。

## 产品级控制

领域产品在套件基线之上贡献各自的加固能力，例如：

- **内置证书颁发机构**签发设备证书，配合设备认证的 mTLS 与证书吊销检查；
- **多因素认证**与一次性恢复码、登录锁定与会话级即时吊销；
- 对危险操作的**二次确认**，并拒绝机器身份执行；
- 在凭据失陷或流量异常时**隔离设备**，同时保留身份与时序数据。
