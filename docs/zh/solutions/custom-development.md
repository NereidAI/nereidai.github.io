# 定制开发

开放平台覆盖了通用的边缘到云端闭环，但每个部署现场都有环境特有的缺口：未纳管的
设备协议、新的加速芯片、受监管的业务流程。**定制开发**就是由厂商团队填平这些缺口
的服务，按工作说明书（SOW）界定范围并交付。

首先要说明：Apache-2.0 已经赋予你自己的团队扩展平台的权利——这是免费的，且永远
免费。本页描述的是另一种选择：由维护者团队承担开发工作，并负交付责任。

!!! note "商业服务，独立协议"
    定制开发按**独立的商业协议（SOW）**交付，不属于 Apache-2.0 社区版。开源与商业
    服务的边界，请见[社区版与企业版](../community/community-vs-enterprise.md)。

## 自助扩展与厂商定制开发

| | 自助扩展 | 厂商定制开发 |
|---|---|---|
| 谁来做 | 你自己的团队 | NereidAI 维护者团队 |
| 法律基础 | Apache-2.0 授予的权利——使用、修改、再分发 | 独立工作说明书，按合作逐案界定 |
| 费用 | 免费 | 收费，按项目报价 |
| 支持 | GitHub issues / Discussions，无 SLA | 专属工程师、里程碑、验收标准 |
| 交付物归属 | 归你所有，遵循 Apache-2.0 条款 | 协议中约定；客户专属交付物归客户所有 |

## 定制开发覆盖什么

范围归入三类，与[开源许可](../community/license.md)页商业选项中的清单一致：

1. **设备与连接器集成**——平台尚未支持的南向协议、PLC 与控制器、传感器及遗留
   系统，以 [NereidEdge](../products/nereidedge.md) 连接器的形式交付。
2. **多厂商芯片 / NPU 加速**——面向新型加速器的适配器插件与量化/导出链路，扩展
   [NereidForge](../products/nereidforge.md) 的多芯片覆盖范围。
3. **行业特定适配**——面向受监管环境的领域工作流、数据模型、规则包与门户/报表
   调整，包括 NereidFactory、NereidSentinel、NereidMedical 等行业解决方案的前期
   工程。

```mermaid
flowchart LR
    REQ["需求与\n现场环境"] --> SOW["界定 SOW\n商业基础事先书面约定"]
    SOW --> BUILD["基于标准\n平台构建"]
    BUILD --> ACCEPT["验收与\n交接"]
    ACCEPT --> LTS["可选 LTS /\n维保"]
```

## 合作如何开展

1. **发邮件**至 [jiekechoo@gmail.com](mailto:jiekechoo@gmail.com)，说明缺口——
   涉及的设备、协议、加速器或工作流。
2. **范围研讨**——环境、约束与具体的验收标准。
3. **SOW 方案**——投入、里程碑与商业基础，开工前一律书面写明。如需先做概念验证，
   另行界定范围且可能收费，口径与[价格与购买](../community/pricing.md)一致。
4. **交付**——基于标准平台构建，不做私有分叉，升级通道始终敞开。
5. **验收与交接**——文档，以及私有化培训与知识转移。
6. **可选维保**——后续变更与 LTS 覆盖通过订阅或维保协议持续。

## 平台为何始终只有一套代码

NereidAI 采用一套代码、没有隐藏功能的 open-core 模式。定制工作以集成与适配的形式
交付在平台**之上**，绝不做私有分叉：客户专属逻辑按协议约定归客户所有，通用、可复用
的增强可经双方同意回馈上游。你的部署始终可以升级，社区版也保留平台本身的全部能力。
